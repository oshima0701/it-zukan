## なぜ画面を作らなかったのか？

2025年、Anthropic が公開しました<Cite n={1} />。見た目は素っ気なく、ターミナルの中で動きます<Cite n={2} />。

理由があります。この道具がやるのは「ファイルを読む」「書き換える」「コマンドを動かす」「結果を見る」の繰り返しです。これらは全部、もともとターミナルの仕事でした。わざわざ別の画面を作るより、そこに住んだほうが素直だったわけです。

おかげで、人が手で作業していた場所と、AIが作業する場所が同じになりました。途中で人が割り込んで手で直し、また任せる、ということができます。

{/* block: naming */}
## 名前の由来：そのまま

もとになっているAIが Claude で、やることがコードを扱うことなので Claude Code です。ひねりはありません。

むしろ注目すべきは、名前に Copilot のような謙譲がないことです。副操縦士ではなく、作業そのものの名前が付いています。この道具がどこまで引き受けるつもりかが、名前に出ています。

{/* block: analogy */}
## たとえ話：鍵を預けた職人

「台所の水漏れを直しておいて」と頼んで、家の鍵を渡して出かけるようなものです。

職人は自分で原因を探し、必要なら床下も開け、部品を替え、水を流して確かめます。いちいち連絡は来ません。帰ってきたら直っています。

便利です。そして、帰ってから**自分で確かめる**必要があります。何をどう直したのか、ほかの場所を触っていないか。鍵を預けるとはそういうことです。

## 最初に覚える3つ

| やること | 効果 |
|---|---|
| 作業の前に記録を残しておく | いつでも元に戻せる |
| 範囲を区切って頼む | 触ってほしくない場所を守れる |
| 結果を自分で動かして確かめる | 動いた報告を鵜呑みにしない |

1つめが効きます。変更を記録しておけば、気に入らなければ丸ごと戻せます。戻せる状態を作ってから任せる、というのが安心して使う条件です。

{/* block: you */}
## あなたとの関係

このサイトも、この道具で作られています。

見えるものを作るだけでなく、「大量のファイルの名前を規則で付け替える」「表の形式を一括で変える」といった、手でやると日が暮れる作業に向きます。プログラムを書く仕事でなくても出番はあります。

{/* block: misunderstanding */}
## よくある誤解：任せれば勝手に正解を出す

出しません。出すのは「それらしい結果」です。

動いたように見えて、確かめていないだけ、ということが起こります。だから、**どうなっていれば成功なのか**を先に決めてから任せるのが要点になります。これは人に仕事を頼むときと同じです。

{/* block: firststep */}
## 今日5分でできること

いきなり大事なファイルを触らせないでください。まず、どうでもいいフォルダを1つ作り、その中だけで頼んでみることです。

「このフォルダに、テスト用のCSVを3つ作って」くらいから始めると、どういう動き方をする相手なのかが分かります。
