## なぜ2週間足らずで作られたのか？

Linux の開発では、世界中から届く変更を managing するために、BitKeeper という他社製の道具を無償で使わせてもらっていました。2005年、その無償利用が終わります<Cite n={1} />。

何万人もが関わる開発が、道具を失いました。代わりが要る。そこでリーナス・トーバルズが自分で書き始めます。

記録に残っている最初のコミットは2005年4月7日<Cite n={3} />。そしてその数日後には、Git 自身の開発を Git で管理できるところまで来ていました<Cite n={1} />。急ごしらえで生まれた道具が、いまや世界中で使われています。

{/* block: naming */}
## なぜ「嫌なやつ」という名前なのか？

Git は、イギリス英語で「嫌なやつ」を指す俗語です。

ただし、ここは慎重に書きます。**作者が「自分にちなんで名付けた」と冗談を言った**という話が広く流通していますが、一次資料にたどり着けませんでした。このページでは採りません。

採れる現物はあります。Git 自身の README に、作者による説明が残っています<Cite n={2} />。そこでは「ばかげた中身追跡ツール」と自称したうえで、気分次第でいろいろな意味に読める、として複数の候補が並べられています。意味のない3文字の組み合わせ、見下げ果てたやつ、global information tracker、といった具合です<Cite n={2} />。

**どれが本当とも書いていない**ところが、この名前の由来です。真面目に1つの答えを探すほうが野暮だ、という態度そのものが残されています。

{/* block: analogy */}
## たとえ話：ゲームのセーブポイント

難所の前でセーブして、失敗したら読み込み直す。Git がやっていることはこれです。

違うのは、セーブが一本道ではない点です。あるセーブ地点から枝分かれして、別の筋道を試せます。うまくいけば本筋に合流させ、だめなら枝ごと捨てます。本筋は無傷のままです。

「最終版_本当に最終_v3.docx」が生まれるのは、この枝分かれと合流を手でやろうとしているからです。

## 最初に覚える3つ

| やりたいこと | 書き方 |
|---|---|
| いまの状況を見る | `git status` |
| ここまでを記録する | `git add .` のあと `git commit -m "説明"` |
| これまでの記録を見る | `git log --oneline` |

1つめが効きます。迷ったら `git status` と打つ。何が変わっていて、次に何ができるかを教えてくれます。Git は怖がられますが、現在地を聞けば必ず答えてくれる道具です。

{/* block: you */}
## あなたとの関係

ファイル名に日付を付けて増やしていく運用に心当たりがあるなら、それが手作業の Git です。

`提案書_20260301.xlsx`、`提案書_20260301_修正.xlsx`、`提案書_最新.xlsx`。どれが最新か分からなくなり、中身を開いて見比べる。Git が引き受けるのは、まさにこの作業です。

{/* block: internet */}
## ネットでの扱われ方

`git blame` という命令があります。直訳すると「責める」。どの行を誰がいつ書いたかを表示する機能で、名前の物騒さがよくネタにされます。

実際の使い道は犯人探しではなく、「この妙な1行は、どういう事情で入ったのか」を調べることです。たいてい、過去の自分が出てきます。

{/* block: misunderstanding */}
## よくある誤解：Git と GitHub は同じもの

別物です。Git は手元で動く道具、GitHub はその記録を預けて見せ合う場所です。

Git だけでも完全に使えます。ネットにつながっていなくても、記録も枝分かれも巻き戻しもできます。GitHub がなくても困りません。逆に、GitHub は Git の記録を前提にしています。

{/* block: firststep */}
## 今日5分でできること

適当なフォルダを1つ作り、その中でターミナルを開いて `git init` と打ってください。それだけで、そのフォルダは記録が取れる状態になります。

テキストファイルを1つ作り、`git add .`、`git commit -m "最初"` と打つ。`git log` で、いま打った記録が見えます。
