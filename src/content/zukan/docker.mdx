## 5分の発表から始まった

2013年3月、ある会議の5分間の発表枠で、ソロモン・ハイクスが Docker を紹介しました<Cite n={1} />。前触れのない、小さな枠でした。

解こうとしたのは、昔からある苛立ちです。**「わたしのパソコンでは動くんですが」。** 開発した人の手元では動くのに、別の場所に持っていくと動かない。入っている部品の版が違う、設定が違う、OSが違う。

答えは、プログラムだけを渡すのをやめることでした。動くのに必要な環境ごと箱に詰めて、箱ごと渡す。相手は箱を開けずにそのまま動かす。これなら、相手のパソコンの事情は関係なくなります<Cite n={2} />。

{/* block: naming */}
## 名前の由来：港湾労働者

docker は英語で**港湾労働者**、船に荷を積み下ろしする人のことです。

この名前は比喩として最後まで一貫しています。荷物を詰める単位を「コンテナ」と呼び、マスコットはコンテナを背負ったクジラ **Moby Dock** です。

比喩のもとになった史実があります。1950年代、輸送用コンテナの規格が世界で統一されました<Cite n={3} />。それまでは荷物の形がばらばらで、港ごとに積み方を考える必要がありました。箱の大きさを決めただけで、船・トラック・鉄道のあいだで荷を積み替えられるようになり、世界の物流が変わりました<Cite n={3} />。

Docker がやったのは、これとまったく同じことです。中身が何であれ、箱の外側の形を揃えた。

{/* block: analogy */}
## たとえ話：引っ越し用の箱

引っ越しのとき、家具を1つずつ運んで、新居で「このネジが合わない」と困るのが従来のやり方です。

Docker は、部屋ごと箱に詰めて運びます。新居では箱を置くだけで、中はもとの部屋のままです。

ただし、箱は軽くありません。同じ箱をいくつも抱えると、手狭になります。

## 最初に覚える3つ

| やりたいこと | 書き方 |
|---|---|
| 箱を動かす | `docker run 名前` |
| いま動いている箱を見る | `docker ps` |
| 止める | `docker stop 名前` |

2つめが大事です。箱は動かしたことを忘れやすく、気づくと何個も動いています。`docker ps` で現在地を確かめる癖をつけてください。

{/* block: you */}
## あなたとの関係

社内のシステムを動かしているのが Docker である、という状況は珍しくありません。手順書に「コンテナを再起動してください」と書かれていたら、それです。

自分で使う場面もあります。データベースを試したいとき、パソコンに直接入れるとあとで消すのが面倒です。箱で動かせば、要らなくなったら箱ごと捨てられます。

{/* block: internet */}
## ネットでの扱われ方

Docker の成り立ちを説明する定番のネタがあります。

「わたしのパソコンでは動くんだけど」→「じゃあ君のパソコンごと出荷しよう」→ Docker 誕生。

乱暴ですが、やっていることの要約としてはかなり正確です。

{/* block: misunderstanding */}
## よくある誤解：仮想マシンの一種

近いですが違います。仮想マシンは、アプリごとにOSを丸ごと積みます。コンテナは本体のOSを共有し、アプリと必要な部品だけを包みます<Cite n={1} />。

この差が、起動の速さと大きさに出ます。仮想マシンが数分かかるところを、コンテナは数秒で立ち上がります。

ついでに。中身は Linux のしくみを使っています。Windows や Mac で動かすときも、裏では小さな Linux が動いています。**Linux のページのペンギンを覚えていますか。** あれがここにも居ます。

{/* block: firststep */}
## 今日5分でできること

Docker を入れたら、`docker run hello-world` と打ってみてください。

数秒で、挨拶のメッセージが出ます。そのメッセージ自体が「いま何が起きたか」の説明になっています。箱を取ってきて、動かして、終わった。それだけです。
