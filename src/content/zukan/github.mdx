## なぜ「置き場」が会社になったのか？

Git は手元で完結する道具です。だから、記録を置く場所さえあれば、それ以上は要らないはずでした。

2008年に始まった GitHub が足したのは、**置き場ではなく人の居場所**でした<Cite n={1} />。誰かの作ったものを自分の手元に複製し、直して、「こう直しました、取り込みませんか」と送る。その一連のやりとりを画面の上で成立させたのです。

結果として、世界中の開発者が同じ場所に集まりました。2018年、マイクロソフトが買収しています<Cite n={1} />。

{/* block: naming */}
## 名前の由来：Git の hub（中心）

Git の記録が集まる hub、つまり中心地という意味です。素直な名前です。

おもしろいのはマスコットのほうです。**Octocat** は猫とタコを合わせた姿をしています。GitHub のために描き下ろされたものではなく、イラストレーターが素材サイトで販売していた絵を GitHub が見つけて使い始めた、という経緯が記録されています<Cite n={1} />。

いまでは GitHub の顔として扱われ、使い方の決まりも公式に示されています<Cite n={2} />。拾ってきた絵が会社の看板になった形です。

{/* block: analogy */}
## たとえ話：図書館ではなく、公民館

本を預かって並べておく場所、と考えると半分しか合っていません。

実際の GitHub は公民館です。人が集まり、掲示板に「ここが壊れています」と貼り紙をし、別の人が「直しておきました、見てください」と持ってくる。貸し借りよりも、やりとりのほうが中心にあります。

だから、ただ置いておくだけでは半分しか使っていないことになります。

## 最初に覚える3つ

| やりたいこと | どうするか |
|---|---|
| 他人のものを手元に複製する | クローンする |
| 自分の変更を送る | プッシュする |
| 他人の変更を取り込む | プルする |

この3つの言葉は、用語辞典のほうに説明があります。GitHub の画面で迷ったら、まず「いま手元と置き場のどちらの話をしているのか」を確かめてください。たいていの混乱はここから来ます。

{/* block: you */}
## あなたとの関係

いま読んでいるこのサイトも、GitHub に置かれています。文章を1つ直して記録を送ると、数十秒後には公開されているページが入れ替わります。

プログラムに限りません。文書、設定、レシピ、議事録。履歴が残ってほしいものなら何でも置けます。

{/* block: internet */}
## ネットでの扱われ方

日本では、活動記録の緑のマス目を**「草」**と呼びます。記録を残した日が濃い緑になり、続けるほど緑が増える表示です。ネットスラングの「草」と重なって、「草を生やす」という言い方が定着しました。

もうひとつ。2020年、GitHub は北極圏ノルウェーの廃坑に、特殊なフィルムに焼いたコードを保管する計画を実施しました<Cite n={3} />。1000年保つことを狙ったものです<Cite n={3} />。

{/* block: misunderstanding */}
## よくある誤解：置いたものは自分のものだから自由

公開の設定にすると、世界中の誰でも読めます。ここを取り違えた事故が後を絶ちません。

とくに、接続先の情報や鍵のような秘密を、気づかずに一緒に送ってしまう事故です。一度公開された内容は、あとから消しても記録に残ります。何を置いているかは、置く前に見る習慣が要ります。

## 今日5分でできること

GitHub でアカウントを作り、自分の名前の付いたページを見てみてください。

そのあと、誰か有名な人のページで、適当なプロジェクトを開いてみてください。右上の数字が、そのプロジェクトを気に入った人の数です。文章の書かれ方、議論の進み方を眺めるだけでも、何が起きている場所なのか分かります。
