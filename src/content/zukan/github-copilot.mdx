## なぜ「書く」より「続ける」を選んだのか？

2021年、GitHub と OpenAI が組んで公開しました<Cite n={2} />。当初は試用版で、誰でも使える形になったのは2022年です<Cite n={2} />。

目の付けどころは、**全部書かせないこと**でした。人がエディタで文字を打っている最中に、その続きとして自然なものを薄く表示する。気に入ればキーひとつで採用し、気に入らなければ打ち続ける。

この形には利点があります。人が主導権を持ったまま、手数だけが減ります<Cite n={1} />。「指示して待つ」のではなく「書きながら受け取る」ので、作業の流れが途切れません。

{/* block: naming */}
## 名前の由来：副操縦士

copilot は航空機の副操縦士です<Cite n={2} />。

この名前は役割分担の宣言です。**機長は人のまま。** 副操縦士は計器を読み、手順を思い出させ、手を貸しますが、行き先を決めるのも、最終的な操縦桿を握るのも機長です。

AIの道具の名前としては、かなり抑制的な部類に入ります。

{/* block: analogy */}
## たとえ話：先回りする同僚

隣の席の同僚が、あなたが書き始めた文を見て「それ、こう続くんじゃない？」と言ってくる。合っていればそのまま使い、違えば「いや違う」と言って自分で書く。

便利ですが、注意点も同じです。同僚の案をろくに読まずに毎回採用していたら、でき上がったものを自分で説明できなくなります。

## 最初に覚える3つ

| やること | 効果 |
|---|---|
| コメントで先に意図を書く | 書いた意図に沿った続きが出やすくなる |
| 候補を採る前に読む | 読める範囲だけが自分の資産になる |
| 候補を切り替えて見比べる | 1つ目が最良とは限らない |

2つめは技術ではなく習慣です。ここを省くと、動くけれど誰も中身を知らないものが増えます。

{/* block: you */}
## あなたとの関係

プログラムだけでなく、設定ファイルや定型の文書でも働きます。規則性のある繰り返しほど、よく当たります。

一方、業務の事情が絡む判断は当たりません。「この値は取引先ごとに違う」といった事情は、画面の外にあるからです。

{/* block: misunderstanding */}
## よくある誤解：プログラムが書けなくても使える

書けない人が使うと、**間違いに気づけません。**

Copilot が差し出すのは「それらしい続き」であって「正しい続き」ではありません。読んで判断できる人の手数を減らす道具であって、読めない人の代わりになる道具ではありません。

{/* block: firststep */}
## 今日5分でできること

VS Code に拡張として入れて、新しいファイルに日本語でコメントを1行書いてみてください。「日付を YYYY-MM-DD の形にする関数」のように。

出てきた候補を、採用する前に声に出して読んでみてください。読んで意味が分かるかどうかが、使ってよいかの分かれ目です。
