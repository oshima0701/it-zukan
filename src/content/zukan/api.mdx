## なぜ「中を見せない」ことが大事なのか？

ソフトが別のソフトの中身を直接いじれると、一見便利です。しかし、いじられる側は二度と作りを変えられなくなります。変えた瞬間、いじっていた側が全部壊れるからです。

そこで、**決まった頼み方だけを外に出し、中身は隠す**という作法が生まれました<Cite n={2} />。使う側は頼み方だけを知っていればよく、作る側は頼み方さえ守れば中を自由に作り替えられます。

この約束が API です。窓口を決めることで、両側が独立して動けるようになります。

{/* block: naming */}
## 名前の由来：応用の側との接点

API は Application Programming Interface の頭文字です<Cite n={1} />。

大事なのは最後の **Interface（接点・境界面）** です。機能そのものではなく、機能と外界との**境目**を指しています。

日本語にすると「アプリを作るための接点」。何を外に出し、何を隠すかを決めた境界線、という意味です。

{/* block: analogy */}
## たとえ話：レストランの店員

客は厨房に入りません。メニューから選んで店員に伝え、料理が運ばれてきます。

店員が API です。客は決まった頼み方（メニュー）しかできませんが、そのかわり厨房の事情を知らずに済みます。厨房は、客に断らずに調理器具を入れ替えられます。

客が厨房に入れる店は、厨房を改装できません。これが「中を見せない」理由です。

## 最初に覚える3つ

| 言葉 | 意味 |
|---|---|
| エンドポイント | 頼みごとの宛先（住所にあたる） |
| リクエスト / レスポンス | 頼みと、その返事 |
| 認証キー | 「わたしは頼んでよい人です」の証明 |

3つめは慎重に扱う必要があります。キーが漏れると、他人があなたの名前で頼めてしまいます。設定ファイルに書いたまま公開の置き場に送ってしまう事故が、後を絶ちません。

{/* block: you */}
## あなたとの関係

地図アプリに飲食店の情報が出る、家計簿アプリが銀行の残高を取ってくる、予約サイトに空室状況が出る。全部 API です。

業務でも使えます。社内システムに API があれば、Excel で手作業していた転記を自動化できます。「あのシステム、APIありますか」と聞けるかどうかで、できることが変わります。

{/* block: incident */}
## 扉が開かなくなった話（2021年）

2021年10月、ある大手サービスで大規模な障害が起きました。復旧作業に向かった社員が、社屋や会議室の扉を開けられなかったと報じられています<Cite n={3} />。

入退室の管理も、社内のしくみに頼んで動いていたためです。頼る先がひとつにまとまっていると、そこが止まったときに**復旧作業そのものができなくなる**。これがこの出来事の教訓です。

{/* block: misunderstanding */}
## よくある誤解：API があれば何でもできる

できるのは、相手が用意した頼み方の範囲だけです。

「このデータが取れるはず」と思っても、窓口に無ければ取れません。また、回数の上限や利用条件が決められていることがほとんどです。「API があるか」ではなく「何ができる API か」を確かめる必要があります。

{/* block: firststep */}
## 今日5分でできること

ブラウザのアドレス欄に、公開されている API の宛先を打ち込んでみてください。たとえば郵便番号から住所を返す無料のものがあります。

返ってくるのは、人向けに整えられていない、記号の並んだ文字列です。あの見た目が、ソフト同士のやりとりの素顔です。
