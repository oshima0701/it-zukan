## なぜ「部品を入れる道具」が必要なのか？

よく使う処理は、たいてい誰かが書いて公開しています。表計算を読む、画像を縮める、日付を扱う。自分で書く必要はありません。

ただし、公開されているものを手で集めるのは大変です。場所を探し、落とし、置き場所に配り、更新があればまた繰り返す。

pip は、その手間を1行に畳みます<Cite n={1} />。`pip install 名前` と打てば、探して、落として、使える場所に置くところまでやります。

{/* block: naming */}
## 名前の由来：終わらない説明

pip は「pip installs packages（pip は部品を入れる）」の略だとされています<Cite n={2} />。

説明しようとすると、説明の中にまた pip が出てきます。その pip を説明しようとすると、また出てきます。永遠に終わりません。

これは技術者の昔からの冗談の型です。「自分で自分を説明する名前」をわざと付けて面白がる文化があります。

{/* block: analogy */}
## たとえ話：通販で頼んだら箱がいくつも届いた

棚を1つ注文したつもりが、ネジの箱、工具、説明書、さらにその工具用の部品まで一緒に届く。

pip も同じです。1つ入れると、それが必要としているものまで芋づる式に入ります。数十個になることもあります。

便利ですが、「自分が何を入れたか」を把握しにくくなります。

## 最初に覚える3つ

| やりたいこと | 書き方 |
|---|---|
| 入れる | `pip install 名前` |
| いま何が入っているか見る | `pip list` |
| 入っているものを控える | `pip freeze > requirements.txt` |

3つめが実務で効きます。入っているものを一覧として書き出しておけば、別のパソコンで同じ状態を再現できます。「わたしの環境では動く」を避ける第一歩です。

{/* block: you */}
## あなたとの関係

Python で何かしようとすると、ほぼ必ず最初に出てくるのが pip です。手順書の1行目が `pip install` で始まることは珍しくありません。

ただし、何も考えずに入れ続けると、パソコンの中が散らかります。そこで出てくるのが仮想環境の話です。

{/* block: misunderstanding */}
## よくある誤解：入れたものは安全

公開されている部品は、誰でも登録できます。名前が似ているだけの、まったく別のものが混ざっていることがあります。

打ち間違いを狙って、よく使われる部品に似た名前で悪意あるものを登録する手口が知られています。入れる前に名前を確かめる、公式のページから名前を取る、という習慣が要ります。

{/* block: firststep */}
## 今日5分でできること

ターミナルで `pip list` と打ってみてください。すでに何が入っているかが一覧で出ます。

何も入れた覚えがなくても、いくつか並んでいるはずです。Python を入れた時点で付いてくるものです。
