## なぜエディタごと作り直したのか？

AIの補助を、既存のエディタに拡張として足す。これが先行する形でした。

Cursor はそこを変えました。**エディタの側をAI前提で組み直す**という発想です。土台には VS Code を使い、その上にAIと一緒に書くための仕組みを足しています<Cite n={1} />。

なぜ作り直す必要があったのか。拡張という立場では、エディタの中心的な振る舞いに手を入れられないからです。たとえば「複数のファイルをまたいでまとめて直す」「直した結果を元と並べて見せる」といった働きは、画面の作りそのものに関わります。

{/* block: naming */}
## 名前の由来：文字を打つ位置の印

cursor は、画面で文字が入る位置を示すあの点滅する棒のことです。

もともとは計算尺の、目盛りを読むために滑らせる透明な板を指す言葉でした。ラテン語で「走る者」という意味があります。

エディタの名前としては、これ以上ないくらい素直な命名です。人が文字を打つ、まさにその位置。AIが手を貸すのもそこだ、という置き方になっています。

{/* block: analogy */}
## たとえ話：赤入れされた原稿が返ってくる

頼むと、原稿に赤が入って返ってきます。どこをどう直したかが、元の文と並べて表示されます。

あなたの仕事は、赤入れを一か所ずつ見て、受け入れるか突き返すかを決めることです。まとめて全部受け入れるボタンもありますが、それを押し続けると、自分の原稿ではなくなっていきます。

## 最初に覚える3つ

| やること | 効果 |
|---|---|
| 直してほしい範囲を選んでから頼む | 関係ない場所まで触られない |
| 差分を1か所ずつ見る | 読める範囲だけが自分の資産になる |
| 何をしたいかを先に書く | 意図のずれが早く分かる |

## あなたとの関係

VS Code をもとにしているので、見た目も操作もほぼ同じです<Cite n={1} />。拡張や設定の多くもそのまま持ち込めます。

乗り換えの敷居が低いのは、このためです。一方で、見た目が同じだからこそ「いつのまにかAIに大きく書き換えられていた」ということも起きます。

{/* block: misunderstanding */}
## よくある誤解：VS Code の設定がそのまま全部動く

多くは動きますが、全部ではありません。公式の配布物に紐づいた一部の機能や拡張は、そのまま使えない場合があります<Cite n={2} />。

VS Code のページで触れた「配布されているものと、公開されているソース」の違いが、ここで効いてきます。

{/* block: firststep */}
## 今日5分でできること

既存のファイルを開き、一部を選択して「この部分が何をしているか、コメントで説明を足して」と頼んでみてください。

返ってきた差分を、受け入れる前に読んでください。説明が間違っていたら、それは読めていない証拠です。消して構いません。
