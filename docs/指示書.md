# 指示書：日本人初心者向け「IT技術図鑑」サイトの制作

> この文書は依頼の原文です。**内容を書き換えません。**
> ここに書かれた雑学・エピソードは**すべて候補であり未確認**です(6節の注意書きを参照)。
> この原文に対して、こちらで決めたこと・解釈したことは `設計書.md` に書いてあります。
> 受領後に会話で追加された指示は、末尾の「受領後の追加指示」にまとめています。

## 0. あなたへの依頼

日本人のプログラミング初心者が、IT技術(Git、Python、Dockerなど)を楽しみながら記憶に残る形で学べる、図鑑形式のWebサイトを作ってください。スマホ・PCのどちらからでも快適に読めることが必須です。

進め方は「7. 作業の進め方」に従い、まず少数のサンプルページで型を固めてから全項目に広げてください。不明点や判断が分かれる点は、勝手に決めずに確認してください。

## 1. コンセプト

- ポケモン図鑑のように、各技術を「キャラクター」として紹介する
- 各技術に「誕生年・生みの親・出身地・名前の由来・マスコット・性格」を持たせ、人物・物語・意外性で覚えられるようにする
- 対象読者:プログラミング未経験〜初心者の日本人(子どもではなく大人を想定。ただし専門用語には必ず説明をつける)
- 文体:やさしい「です・ます」調。専門用語は初出時に一言で説明する
- 確認クイズ・フラッシュカードは作らない

## 2. 技術仕様

- 静的サイト(推奨:Astro。より適した選択肢があれば提案してから採用)
- 1項目＝1つのMarkdownファイルで管理する。誕生年・作者・出身地・マスコット・分類・関連項目などは冒頭のメタデータ(frontmatter)に書き、図鑑カード・年表・相関図・世界地図に自動反映させる
- レスポンシブデザイン:スマホは1カラム、PCは目次サイドバー付き
- ダークモード対応
- オフラインでも読めるようにする(PWA)
- 読んだページの記録はブラウザ(localStorage)に保存。使えない環境でも表示が壊れないようにする
- 公開先:GitHub Pages(GitHub Actionsで自動デプロイ)
- 図解はSVGで自作する(権利の心配がなく、スマホでも鮮明)
- 表示速度を重視し、画像は最適化・遅延読み込みする

## 3. 1ページ(1項目)の構成

全ページで同じ配置にそろえる(毎回同じ型だと、読者は中身に集中できる)。

1. 冒頭の「意外な一文」:常識をくつがえす一文(例:「Pythonの名前はヘビではなく、コメディ番組から来ています」)
2. 図鑑カード
   - 名前・読み方(例:Git(ギット))
   - 分類(タイプ):言語タイプ／道具タイプ／場所タイプ／仕組みタイプ など
   - ひとことで(一行説明)
   - 誕生年・生みの親・出身地
   - マスコット(名前と由来)
   - ステータス(難易度・人気・活躍場所)をレーダーチャートで表示
3. 誕生物語:「困りごと → 発明 → その後」の三幕構成。見出しは問いの形にする(例:「なぜGitは『嫌なやつ』という名前なのか?」)
4. 名前の由来(目玉コーナー)
5. たとえ話:サイト全体で統一した世界観(下記「5.」参照)で説明
6. 図解:最低1枚。説明文のすぐ隣に配置する
7. 写真:生みの親や歴史的な物(使える場合)
8. 得意技:最初に覚えるコマンドや書き方を3つまで
9. あなたとの関係:読者の身近な体験とのつながり(例:「あなたのスマホにもSQLiteが入っています」)
10. ネットでの扱われ方:ミーム、あるある、ネタ
11. やらかし事件簿:該当する有名な出来事(笑い話ではなく教訓として書く)
12. よくある誤解:俗説と真実
13. 相棒・ライバル:関連項目へのリンク
14. 最初の一歩:今日5分でできること
15. 無料教材:外部リンク(完全無料のものを優先し、一部有料のものは明記)
16. 今日のひとこと:ページ末尾に、一番覚えてほしいことを一文で
17. 出典:ページ内の事実すべての出典リンク

**強調ルール**:各ページで「一番覚えてほしい一文」だけを色や大きさで目立たせる。強調は1ページ1か所に限定する。

## 4. 記憶に残すための設計原則(すべてのページで守る)

- 絵と言葉をセットに:図や写真を説明文と離さず並べる
- 意外性:予想を裏切る事実を冒頭に置く
- 好奇心を先に:見出しは答えではなく問いにする
- 物語:事実の羅列ではなく、流れのある話にする
- 人物を出す:生みの親の顔と人間関係を見せる
- 感情を動かす:笑い・驚き・共感を入れる
- 自分ごと化:読者の身近な体験につなげる
- 比べる:似たもの同士は比較図で違いを見せる
- 詰め込まない:1ページで覚えるポイントは3つまで
- 最初と最後:冒頭に意外な一文、末尾に今日のひとこと
- 再会させる:別のページで同じ人物・話題をさりげなく再登場させる(例:Dockerのページで「中身はLinux。ペンギンのTuxを覚えていますか?」)

## 5. サイト全体のしかけ

- **町の地図(トップページ)**:サイト全体を一つの町に見立てる。各技術を場所として配置し、地図から各ページに行ける
  - 例:ターミナル通り、Git図書館(日記帳を保管)、GitHub中央図書館、Docker港(引っ越し用の箱)、クラウド空港、APIレストラン(注文を運ぶ店員)、データベース倉庫
  - たとえ話はこの世界観で統一する
- **図鑑登録システム**:読んだページに「登録済み」スタンプ。トップに「12/30種 発見」のような登録率を表示
- **年表ページ**:1947年の「バグ」から現在まで一本の線で並べる
- **人物相関図**:生みの親同士・技術同士のつながり
- **世界地図**:各技術の出身地にピンを立てる
- **ランダム豆知識ボタン**:押すたびに違う雑学を表示
- **やらかし事件簿ページ**:年表形式。内容と教訓
- **エンジニアあるあるページ**
- **ネットスラング辞典**:「草を生やす」「秒で」「動けばいい」など
- **名言・格言集**
- **よくある誤解まとめ**
- **日本発の技術コーナー**:Ruby、日本語プログラミング言語「なでしこ」、絵文字の話など

### 6-2. 項目別ネタ候補

**Git**

- 2005年、リーナス・トーバルズが作成。Linux開発で使っていた管理ツールが使えなくなったのがきっかけ
- 「git」はイギリス英語のスラングで「嫌なやつ」。本人は「自分の名前にちなんだ」と冗談を言っている
- 最初のコミットで、自ら「地獄から来た情報管理ツール」と書いている
- 導入ネタ:「最終版_本当に最終_v3.docx」問題
- `git blame`(直訳「責める」)コマンド
- 「Oh Shit, Git!?!」という、困ったときの解決法サイト

**GitHub**

- 2008年創業、2018年にMicrosoftが買収
- マスコット「Octocat」は猫とタコの合体。もとはイラストレーターのサイモン・オクスリーが素材サイトで販売していた絵
- 日本では活動記録の緑のマス目を「草」と呼ぶ。ネットスラングの「草」と重なる
- 2020年、北極圏ノルウェーの永久凍土の地下にコードを1000年保存する計画を実施
- 2020年、標準ブランチ名が「master」から「main」へ

**Python**

- 1989年のクリスマス休暇に、グイド・ヴァンロッサムが作り始めた
- 名前はコメディ番組『空飛ぶモンティ・パイソン』から。ヘビのロゴは後付け
- サンプルコードの「spam」「eggs」も番組ネタ
- `import this` で「Pythonの心得」が表示される
- タブ派 vs スペース派戦争
- Python 2から3への移行に約12年(2008年〜2020年)
- 「Pythonは遅い」いじり
- グイドは引退後、2020年にMicrosoftに入社

**JavaScript**

- 1995年、ブレンダン・アイクが約10日で作った
- Mocha → LiveScript → JavaScriptと改名。当時人気のJavaにあやかっただけで、Javaとはほぼ無関係
- 講演「Wat」:奇妙な挙動で会場が爆笑した伝説の講演
- `typeof null` が「object」になるのは誕生時からのバグ
- 「毎週新しいフレームワークが生まれる」
- 「node_modulesは宇宙で最も重い物体」ミーム

**HTML**

- 1989年、CERNのティム・バーナーズ＝リーが提案。上司が企画書に「あいまいだが面白い」と書き込んだ
- 世界初のWebサイトは今も閲覧できる
- 「HTMLはプログラミング言語か」論争

**CSS**

- 1994年、ホーコン・ウィウム・リーが提案
- たとえ:HTMLは骨組み、CSSは服
- 「CSS is awesome」マグカップ(文字が枠からはみ出すジョークグッズ)

**SQL**

- 1970年代にIBMで誕生。もとは「SEQUEL」で、商標の問題で改名
- 読み方は「エスキューエル」派と「シークェル」派に分かれる
- xkcd「ボビー・テーブルズ君」(SQLインジェクションの説明)

**MySQL**

- 「My」は開発者モンティ・ワイデニウスの娘の名前。MariaDBはもう一人の娘の名前
- イルカのマスコット「Sakila」は公募で命名

**SQLite**

- スマホやブラウザなど身近な場所に入っており、世界で最も多く使われているデータベースの一つ
- ライセンスの代わりに「祝福の言葉」が書かれている

**ターミナル / bash / Vim**

- 昔のテレタイプ端末の名残
- 「shell(殻)」はOSの中心部を包む外側の殻
- 「bash」は「Bourne Again Shell」。作者名と「生まれ変わり」をかけたダジャレ
- 「Vimの終了方法がわからない」:Stack Overflowで100万人以上の役に立ったと発表された質問
- 「rm -rf」の恐怖:『トイ・ストーリー2』のデータが消えかけ、在宅勤務中の社員の家のバックアップで救われた話
- Vim派 vs Emacs派のエディタ戦争

**pip / npm**

- pipは「pip installs packages」の略(再帰的なジョーク)
- npmにはウォンバットのマスコットがいる
- left-pad事件(2016年):11行の小さな部品の公開停止で、世界中の有名ツールが動かなくなった

**Linux**

- 1991年、フィンランドの大学生リーナスが「ただの趣味」と投稿して公開
- マスコットのペンギン「Tux」。リーナスが動物園でペンギンにかまれた話が由来の一つとして語られる
- 「今年こそLinuxデスクトップの年」ミーム
- リーナスは2018年に一度休みを取り、態度を改めると宣言

**Docker**

- 2013年、ソロモン・ハイクスが短い発表で公開し、一気に広まった
- マスコットはコンテナを背負ったクジラ「Moby Dock」
- 「コンテナ」は輸送用コンテナが由来。1950年代の規格統一で世界の物流が変わった話と重ねる
- ミーム:「私のパソコンでは動くんだけど」→「じゃあ君のパソコンごと出荷しよう」→ Docker誕生

**クラウド**

- ネットワーク図でインターネット部分を雲の絵で描いたことが由来
- 「クラウドなんてない。他人のコンピュータがあるだけだ」ステッカー
- AWS S3障害(2017年):作業中のコマンド入力ミスが原因
- 「us-east-1が落ちるとインターネットの半分が落ちる」

**HTTP / API**

- 「418 I'm a teapot」はエイプリルフールのジョーク仕様から
- 「404はCERNの404号室が由来」は俗説
- APIのたとえ:レストランで注文を運ぶ店員
- Facebookの大規模障害(2021年):社員が社屋に入れなくなったとも報じられた

**React / Flask / Django**

- React:2013年にFacebook(現Meta)が公開。ロゴは原子
- Flask:エイプリルフールのジョークから始まった
- Django:ジャズギタリストのジャンゴ・ラインハルトにちなむ

**セキュリティ**

- 「hunter2」:パスワードが伏せ字になると信じた人の古典ジョーク
- よく使われるパスワードランキングで「123456」が上位常連
- xz事件(2024年):処理が0.5秒遅いことに気づいた開発者が裏口を発見
- CrowdStrike障害(2024年):更新ミスで世界中のWindowsが停止

**生成AI**

- 「バイブコーディング」(2025年に広まった言葉)
- ハルシネーション(もっともらしい嘘)

**正規表現**

- 格言「問題を正規表現で解こうとすると、問題が2つになる」

**将来追加項目のマスコット**

- Go:ホリネズミのGopher
- Rust:カニのFerris
- Kubernetes:ギリシャ語で「操舵手」
- PostgreSQL:ゾウのSlonik
- Ruby:日本人のまつもとゆきひろ氏が作成。名前はPerl(真珠)に続く誕生石から

### 6-3. プログラミング全般のネタ

- Hello, World!:1970年代のC言語の解説書から広まった
- ラバーダック・デバッグ
- 0.1 + 0.2 が 0.3 にならない
- 「金曜日にリリースするな」「動いているコードには触るな」「仕様です」
- バグ:1947年、グレース・ホッパーのチームが本物の蛾を記録に貼った(言葉自体はそれ以前からあった)
- 江南スタイル事件(2014年):YouTubeの再生回数が想定の上限を超えた
- 2000年問題・2038年問題
- Excelが遺伝子名を日付に変換する問題(2020年に遺伝子名が変更された)
- 火星探査機の単位ミス(1999年)

### 6-4. 日本のネット界隈ネタ

- 「IT業界のサグラダ・ファミリア」(みずほ銀行のシステム統合)
- 文字化け(「縺」が並ぶ現象。文字コードの解説ページにする価値あり)
- 全角スペース混入エラー
- Excel方眼紙
- 「プログラマー35歳定年説」
- 「エンジニアの『ちょっと見てもらえますか』は1時間かかる」

### 6-5. よくある誤解

- 「404はCERNの404号室が由来」→ 俗説
- 「シヴィライゼーションのガンジーが核を使うのはバグ」→ 作者が否定した伝説
- 「バグという言葉は蛾の事件から生まれた」→ それ以前からある
- 「JavaとJavaScriptは兄弟」→ ほぼ無関係

## 7. 図解と写真

### 図解(SVGで自作)

- Git:セーブポイント、ブランチの分岐と合流
- GitHub:パソコンとGitHubの行き来(プッシュ・プル)
- Docker:コンテナと仮想マシンの比較、輸送コンテナとの対比
- ターミナル:OSを包む殻
- ファイル・パス:フォルダの木構造
- HTTP / API:レストランの店員
- HTML / CSS:骨組みと服
- SQL:表からデータを取り出す
- クラウド:ネットワーク図の雲マーク
- 比較図:Git vs GitHub、Python vs JavaScript など
- サイト全体:町の地図、年表、人物相関図、世界地図

### 写真

- 生みの親:リーナス・トーバルズ、グイド・ヴァンロッサム、ティム・バーナーズ＝リー、グレース・ホッパー、まつもとゆきひろ氏など
- 歴史的な物:1947年の蛾が貼られた作業記録、世界初のWebサーバーのコンピュータ、テレタイプ端末、輸送用コンテナ船、北極圏のコード保管庫
- 世界初のWebサイトの画面

### 権利に関するルール(必ず守る)

- 写真はWikimedia Commonsなど利用条件が明記された画像のみ使用し、各画像に撮影者・ライセンス・出典を表記する
- パブリックドメインとされる画像も個別に確認する
- ロゴ・マスコット画像は各団体の権利物。利用規約を確認し、許可が不明なものは使わず公式ページへのリンクにとどめる
- マスコットを似せたイラストは描かない
- 雑学の文章は自分の言葉で書き、他サイトの文章を転載しない
- 使用した画像の一覧(クレジットページ)を作る

## 8. 作業の進め方

1. **設計**:サイト構成、Markdownのメタデータ項目、ページテンプレート、町の地図の配置案を提示し、確認を取る
2. **サンプル作成**:Git、Python、Dockerの3ページだけを完成させ、スマホとPCの両方で表示を確認できる状態にして見せる
3. **フィードバック反映**:型を修正
4. **全項目に展開**:6-1の1〜8を作成。各ページで事実確認と出典付けを行う
5. **全体ページ**:町の地図、年表、相関図、世界地図、事件簿、あるある、スラング辞典、格言集、誤解まとめ、日本発コーナー、クレジット
6. **公開**:GitHub Pagesへの自動デプロイを設定
7. **最終チェック**
   - スマホ幅(375px程度)とPC幅で全ページの表示確認
   - リンク切れチェック
   - すべての事実に出典があるか確認
   - すべての画像にクレジットがあるか確認
   - 表示速度の確認

## 9. 完成の条件

- 全ページが同じ構成でそろっている
- スマホ・PCの両方で快適に読める
- すべての事実に出典がつき、すべての画像にクレジットがある
- 確認クイズ・フラッシュカードは含まれていない
- 新しい項目を、Markdownファイルを1つ追加するだけで増やせる
